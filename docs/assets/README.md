# README sampling figure

`synthetic-sampling.png` shows the real output of the hardware-free RGB bridge,
not a camera recording or biological response measurement. The image contains
only the known gray background and dark rectangle generated by the CLI.

From a repository checkout with the Python environment activated:

```sh
python -m pip install -e ".[analysis]"
python -m flyvisionbridge.cli --demo --eyes both --output outputs/readme-demo
python scripts/render_readme_demo.py outputs/readme-demo
```

Use a new demo directory on subsequent runs. The renderer accepts only synthetic
CLI output and the exact known stimulus, and never opens a camera.

With the included mapping and assumed demo intrinsics (640 × 480,
`fx = fy = 600`, principal point 319.5, 239.5), the 1,779 target IDs yield 211
observed channels: 106 left and 105 right. There are 1,483 out-of-view channels
and 85 missing directions; both remain null. The coverage count is specific to
this geometry, not a performance or biological validation score. The full
reproducible numerical output is the local `channels.json`.
